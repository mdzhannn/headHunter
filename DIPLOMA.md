## 1. Введение

В условиях современного рынка труда Казахстана существует острая потребность в удобных цифровых инструментах для поиска работы и подбора персонала. Платформа **job.kz** — это полнофункциональная веб-система, которая соединяет соискателей и работодателей, обеспечивая прозрачный и эффективный процесс найма.

Система реализована как монорепозиторий, включающий серверную часть (backend) на Java/Spring Boot и клиентскую часть (frontend) на React/TypeScript.

## 2. Цели и задачи

### Цель
Разработать современную, масштабируемую веб-платформу для поиска работы с поддержкой ролей пользователей, модерацией контента и общением в реальном времени.

### Задачи

- Реализовать регистрацию и аутентификацию пользователей через email OTP + пароль (JWT)
- Создать личный кабинет соискателя с управлением резюме и просмотром вакансий
- Создать кабинет работодателя с управлением компанией и вакансиями
- Реализовать систему откликов с сохранением снимка резюме на момент отклика
- Разработать чат в реальном времени между соискателем и работодателем (WebSocket)
- Создать панель администратора с модерацией и audit log
- Обеспечить контейнеризацию через Docker для простого развёртывания

## 3. Анализ предметной области

### Роли пользователей

| Роль | Описание |
|------|----------|
| **CANDIDATE** | Соискатель — создаёт резюме, откликается на вакансии, переписывается с работодателем |
| **EMPLOYER** | Работодатель — регистрирует компанию, публикует вакансии, просматривает отклики |
| **BOTH** | Совмещает обе роли |
| **ADMIN** | Администратор — модерирует контент, управляет пользователями |

### Статусы модерации

Резюме, вакансии и компании проходят модерацию: `PENDING` → `APPROVED` / `REJECTED`.

### Жизненный цикл отклика

```
Соискатель → Отклик → JobApplication (снимок резюме) → Создание чата → Первое сообщение работодателя → Диалог
```

### Паттерны и принципы

- **MVC** — разделение контроллеров, сервисов и репозиториев
- **DTO** — передача данных через Data Transfer Objects
- **Repository Pattern** — Spring Data JPA репозитории
- **AOP (Aspect-Oriented Programming)** — audit log через `@Around` аспект
- **Stateless Auth** — JWT-токены без серверных сессий
- **Snapshot Pattern** — снимок резюме сохраняется в JSON в `JobApplication.resumeSnapshot`

| `roles` | Роли (CANDIDATE, EMPLOYER, BOTH, ADMIN) |
| `admin_roles` | Суб-роли для администраторов (SUPER_ADMIN, MODERATOR, SUPPORT) |

| `job_applications` | Отклики на вакансии |
| `conversations` | Диалоги (чаты) по откликам |
| `messages` | Сообщения в диалогах |
| `otp_challenges` | OTP-коды для верификации email |

### Ключевые связи

```
User ─── Resume (1:1)
User ─── Company (1:1, как владелец)
Company ─── Vacancy (1:N)
User ─── JobApplication (1:N, как соискатель)
Vacancy ─── JobApplication (1:N)
JobApplication ─── Conversation (1:1)
Conversation ─── Message (1:N)
```

### Особенность: снимок резюме

При создании отклика (`JobApplication`) система сохраняет JSON-снимок резюме в поле `resume_snapshot`. Это позволяет работодателю видеть **резюме таким, каким оно было в момент отклика**, даже если кандидат впоследствии его изменит.

## 7. Функциональные возможности

### 7.1 Аутентификация и регистрация

**Регистрация (3 шага):**
1. Пользователь вводит ФИО и email
2. Система отправляет 6-значный OTP-код на email через Gmail SMTP
3. Пользователь подтверждает код и устанавливает пароль → выдаётся JWT

**Вход:** email + пароль → JWT + refresh token

**Безопасность OTP:**
- TTL кода: 5 минут
- Максимум 3 отправки за 10 минут
- Максимум 5 попыток ввода кода

### 7.2 Кабинет соискателя

- Создание и редактирование резюме (фото, личные данные, опыт, навыки, образование)
- Просмотр одобренных вакансий с фильтрами (город, тип занятости, зарплата, опыт, категория)
- Отклик на вакансию (с автоматическим созданием чата)
- Просмотр истории откликов с резюме на момент отклика
- Чат с работодателем в реальном времени (ответ только после первого сообщения от работодателя)

### 7.3 Кабинет работодателя

- Регистрация и редактирование профиля компании
- Создание/редактирование/удаление вакансий
- Просмотр откликов на вакансии с резюме кандидатов
- Написание первого сообщения в чате с кандидатом
- Каталог всех резюме соискателей

### 7.4 Панель администратора

**Дашборд** с метриками:
- Кол-во пользователей, компаний, резюме, вакансий
- Регистрации за последние 30 дней (график)
- Воронка откликов (всего / рассмотрено / принято / отклонено)

**Модерация:**
- Компании: просмотр, одобрение/отклонение с причиной
- Резюме: просмотр, одобрение/отклонение, массовые действия
- Вакансии: просмотр, одобрение/отклонение

**Управление пользователями:**
- Просмотр всех пользователей
- Создание пользователей
- Блокировка/разблокировка
- Изменение ролей

**Audit Log:**
- Автоматическая запись всех POST/PUT/DELETE действий администраторов
- Сохраняет: кто, что, когда изменил и что было «до»
- Фильтрация по типу сущности, email, датам

### 7.5 Чат в реальном времени

- Работает через WebSocket (SockJS) + STOMP протокол
- JWT-аутентификация при STOMP-подключении
- **Бизнес-правило:** первое сообщение может отправить только работодатель — это защищает кандидатов от спама
- Push-обновления: счётчик непрочитанных обновляется у обоих участников без перезагрузки страницы

## 9. Безопасность

### Аутентификация (JWT)

Каждый запрос к защищённым эндпоинтам содержит заголовок:
```
Authorization: Bearer <JWT>
```

JWT содержит: `sub` (userId), `role` (CANDIDATE/EMPLOYER/ADMIN), `adminRole` (SUPER_ADMIN/MODERATOR/SUPPORT), `exp`.

### Авторизация

| Путь | Требование |
|------|------------|
| `/admin/**` | Роль `ADMIN` |
| `/candidate/**` | Любой аутентифицированный пользователь |
| `/employer/**` | Любой аутентифицированный пользователь |
| `/conversations/**` | Любой аутентифицированный пользователь |
| `/auth/**`, `/vacancies/public` | Публичный доступ |

### Дополнительные меры

- Пароли хранятся в виде **BCrypt-хэша**
- OTP-коды также хранятся в хэшированном виде
- CORS настроен только для разрешённых origins
- Refresh token с ограниченным временем жизни
- Rate limiting для OTP (3 отправки / 10 минут)
- WebSocket соединения также проверяют JWT


### Запуск одной командой

```bash
docker compose up --build
```

### Многоэтапная сборка (Multi-stage build)

**Backend Dockerfile:**
- Этап 1: `eclipse-temurin:17-jdk-jammy` — компиляция и сборка JAR через Gradle
- Этап 2: `eclipse-temurin:17-jre-jammy` — лёгкий образ только с JRE для запуска

**Frontend Dockerfile:**
- Этап 1: `node:20-alpine` — сборка React-приложения (`npm run build`)
- Этап 2: `nginx:alpine` — раздача статики + reverse proxy на backend

### Health Check

PostgreSQL-контейнер имеет healthcheck: backend запускается только после того, как БД готова принимать соединения.

## 12. Заключение

В ходе дипломной работы была спроектирована и реализована полнофункциональная платформа **job.kz** для поиска работы в Казахстане.

**Достигнутые результаты:**

1. Разработана трёхуровневая система ролей (соискатель / работодатель / администратор) с независимыми интерфейсами для каждой роли.

2. Реализована безопасная аутентификация: двухфакторная регистрация через email OTP + пароль, JWT с refresh-токенами, BCrypt-хэширование паролей.

3. Создан чат в реальном времени на основе WebSocket/STOMP с бизнес-правилом «первое сообщение только от работодателя».

4. Внедрена система снимков резюме: работодатель видит резюме именно таким, каким оно было на момент отклика.

5. Разработана admin-панель с модерацией контента, управлением пользователями и автоматическим audit log (AOP).

6. Проект контейнеризирован через Docker Compose и готов к production-развёртыванию.

Платформа демонстрирует применение современных enterprise-паттернов (MVC, DTO, Repository, AOP, Snapshot) и может быть расширена добавлением новых функций: платных размещений, аналитики для HR, мобильного приложения через REST API.
